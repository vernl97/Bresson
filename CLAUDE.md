# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

NLP Studio (`nlp_studio` crate): a standalone Rust application for converting, editing, and managing film negatives. While originally inspired by the Negative Lab Pro Lightroom plugin, **NLP Studio is an independent application designed to modernize, streamline, and meaningfully improve upon the entire film negative workflow**.

It reads camera RAW negatives or TIFF/JPEG/PNG scans, or scans film itself from Plustek OpticFilm scanners and SANE flatbeds, converts them with a density-based print engine, and exports positive copies. A single fast, cross-platform binary provides both an interactive egui GUI and a headless CLI, completely free of Lightroom, catalog databases, or Adobe subscriptions.

### Product Vision & Design Philosophy

- **Modern Photo App UX**: The workflow, layout, and UI/UX are inspired by modern photo editors like Lightroom and Capture One—featuring smooth thumbnail browsing, responsive image previews, non-destructive editing, side-by-side / split before-and-after views, and professional color grading.
- **Purpose-Built for Film Workflows**: Rather than forcing digital camera paradigms onto digitized film, the app delivers tailored quality-of-life improvements specifically for film photographers and scanning labs:
  - **First-class roll handling**: Seamless roll-level workflows, batch roll analysis, cross-frame consistency (outlier-rejected roll curve aggregation), and synchronized roll metadata (film stock, ISO, push/pull, lab, developer).
  - **Automated frame prep**: Intelligent frame detection, crop, and straightening to isolate the active negative from film borders, rebates, and scanner holders.
  - **Direct scanning**: scan straight into a roll from Plustek OpticFilm film scanners (a native Rust driver, no vendor software) and SANE flatbeds with a transparency unit, as linear DNGs that convert like any scan; one box per frame on a flatbed.
  - **Transparent, open sidecars**: Clean, human-readable JSON sidecars (`NLP/<file>.nlp.json`) and shared roll metadata (`NLP/roll.json`) keeping scan folders portable and non-destructive without catalog lock-in.
- **Native Performance & Independence**: Native compiled Rust binary with multi-threaded pipelines (Rayon), fast proxy generation for instant visual feedback, and zero reliance on external hosts or legacy plugin runtimes.

## Commands

```bash
cargo run --release                          # GUI (starts on the Rolls list)
cargo run --release -- /path/to/scans        # GUI on a folder or single file
NLP_FAKE_SCANNERS=1 cargo run --release -- /path/to/roll   # Scan panel with simulated scanners (always on in debug builds)
cargo run --release -- convert [--roll] [--roll-process NAME] [--tone NAME] [--wb NAME] [--lut NAME] [--border PCT] [--auto-crop] [--aspect NAME] [--flat FILE] [--jpg] [--out DIR] FILES
cargo run --release -- scan-prep FILES       # gamma-encode linear TIF scans (Linear Scan source reads them directly)
cargo run --release -- synth [out.tif] [ev]  # write the modelled ColorChecker negative (testchart.rs)

cargo test --release                         # unit tests (engine + app)
cargo test --release <name>                  # single test, e.g. cargo test --release roll_process_modes
cargo test --release chart_quality -- --nocapture   # print the conversion quality metrics
NLP_UI_TEST_DIR=<scans> NLP_UI_OUT=<dir> cargo test --release ui_screens -- --ignored   # headless egui_kittest screenshots
NLP_UI_TEST_DIR=<a roll> NLP_UI_OUT=<dir> cargo test --release rolls_screen -- --ignored  # the start screen's roll rows and their frame strips
NLP_UI_TEST_DIR=<scans> NLP_UI_OUT=<dir> cargo test --release ux_tour -- --ignored      # dialogs and the full editor sidebar, for UI review
NLP_UI_TEST_DIR=<scans> NLP_UI_OUT=<dir> cargo test --release grid_tour -- --ignored    # the roll grid: filters, flags, quick look, negatives, box selection
NLP_UI_OUT=<dir> cargo test --release scan_panel   # Scan panel on simulated scanners (screenshots with NLP_UI_OUT)
cargo test -p opticfilm --release            # OpticFilm driver: parity with pyopticfilm (fixtures: scanners/opticfilm/tools/gen_fixtures.py)
cargo test -p sane --release                 # SANE layer against its simulated flatbed
cargo test -p sane --release -- --ignored    # against real libsane (needs sane-backends): `test` backend via a private SANE_CONFIG_DIR, and the system backends surviving thread exit
cargo test --release worker_scans_from_real_libsane -- --ignored   # the scanner worker against real libsane
NLP_SCAN_DIRS=<rolls>:<folder of rolls> NLP_SCAN_OUT=<dir> [NLP_SCAN_BASELINE=<old stats.json>] \
  cargo test --release real_scans -- --ignored --nocapture   # conversion check on real scans (scan_check.rs)
```

`main.rs` sends `convert | scan-prep | synth | help` to `cli.rs`. Any other argument is treated as a path to open in the GUI.

## Workspace

The root `Cargo.toml` is a workspace: `nlp_studio` (this app) plus two scanner crates in `scanners/`.
- `scanners/opticfilm`: the Plustek OpticFilm driver, a 1:1 Rust port of pyopticfilm over `nusb` (GPL-3, so distributed app builds are GPL-3). Parity is the test oracle: fixtures generated from the Python driver (`tools/gen_fixtures.py`, run in `scanners/pyopticfilm`) demand byte-identical USB traffic and identical images; `tools/gl128_sim.py` / `usb/fake_gl128_sim.rs` simulate the GL128 analog front end so calibrated scans are covered too. Its README lists what is validated. Keep Rust and Python in step when changing behaviour, and regenerate fixtures rather than editing them.
- `scanners/sane`: SANE 1.0 bindings (`ffi.rs`, libsane loaded at runtime with `libloading`; loaded and `sane_init`ed once per process and shared, with every call under one process-wide lock since SANE isn't thread-safe; it is never unloaded and `sane_exit` is never called, because the dll backend would `dlclose` device backends whose thread-exit destructors then crash — `tests/libsane_system.rs` checks this in its own process), film-scan setup and the read loop (`lib.rs`), and a simulated flatbed (`fake.rs`) that the tests and the app's simulated scanner use.
- `scanners/pyopticfilm`: the Python reference (untracked); only needed to regenerate fixtures.

## Architecture

**`src/engine/`**: pure image processing, no UI. `docs/conversion-engine.md` walks through it stage by stage with the functions, constants and formulas; read it before changing the engine and keep it in step with the code. The pipeline for one frame:

1. `decode::load(path, max_long_edge)` → `SourceImage` (linear camera RGB). Bitmaps are read in their embedded ICC profile (`icc.rs`, matrix/TRC; sRGB otherwise). `rawler` handles RAW files; with a size limit, the CFA is binned instead of demosaiced. Full resolution uses `demosaic.rs` (RCD-style) for Bayer and rawler's Markesteijn for X-Trans; scanner DNGs (LinearRaw) need none.
2. `pipeline::resolve_base` finds the film base: the 98.5–99.5 percentile of the *uncropped* frame, or an eyedropper sample, or the roll base.
3. `pipeline::prepare_negative` applies the optional flat field (`flat.rs`), the camera matrix and the base, and stores per-channel **density above the base** (`log10(base / T)`, unclamped), with C-41 dye crosstalk removed and the colour model's calibration applied in density. In density a wrong base is only a constant offset that the levels absorb. No camera profiles (DCP) are used.
4. `pipeline::analyze` builds the 600 px analysis buffer (film border and holder trimmed by density, then the border buffer, σ=2 blur) and finds per-channel `Levels` (density lo/hi/mid; the white end is capped relative to the median so light sources can't darken the print, except that a mostly dark frame with a many-toned bright area clips only its top 3 %). Red and blue are placed on the image's neutral axis, fitted through ten equally weighted tonal steps. Each step's grey is the cluster of near-grey pixels on the current axis (`neutral_cluster`), so a skin, sand or wood surface lit across many tones can't pull it, and steps far off the line are dropped. With enough steps the axis bends: a quadratic stored as `ChannelLevels::bow`, which corrects crossover (Fuji US 6,160,634, EP 0 612 183). Auto-Neutral prints that axis grey. `skin.rs` then finds compact skin areas away from the frame edge and moves the midtone key (`mid`) towards the skin, like the Frontier's face-density Auto Setup. The output is an `Analysis`. In roll mode, `aggregate_roll` builds a `RollBalance`: the film's slopes and bends (medians of the frames') and the roll's filtration (median offset, robust outliers left out), both from frames with a neutral axis of their own. Lab mode prints a frame with a reliable axis exactly as it converts alone; as its confidence drops its levels fade towards the roll's balance at its own density range. `pipeline::auto_wb_for` gives the auto WB that matches whichever levels `levels_for` picks. Darkroom uses the roll's balance and exposure for every frame.
5. `pipeline::Renderer` is built from `Settings` and `Levels` (`levels_for` chooses roll or frame levels). `curve.rs` is the print engine: normalised density → tone/colour shaping → paper log exposure plus filtration (WB, C·M·Y keys, in CC) and print time (EV) → the tone profile (the plugin's 14 profiles, fitted as 21-knot curves over normalised density). The per-channel part is baked into density-indexed LUTs; the profile is one table applied hue-preservingly (`CurveLut::apply_rgb`, the DNG RGBTone that Lightroom uses for a master curve: the largest and smallest channel through the curve, the middle kept at its place between them), so greys print as per channel and colours keep their hue. A base saturation (`DENSITY_SATURATION`) in density keeps chroma near the scene's. Hyper Tone (`dodge.rs`, off by default) adds a density offset before the curves, from a two-scale low-pass of green density, compressing large areas away from the key. Then come the native `look.rs` looks (saturation spares skin tones), output-space conversion with soft gamut compression (`color.rs`) and grain-aware sharpening. Sharpening weighs edges against grain by the local R/G/B correlation of the detail bands; it runs only on CPU renders (exports) with Sharpening set to Lab or Scanner. `export.rs` writes TIFF/JPEG with ICC and EXIF; `scan_dng.rs` writes scanner output as LinearRaw DNG. `contact.rs` tiles rendered frames (rotated to landscape, labelled with ab_glyph and the embedded Inter) into the folder's contact sheet JPEG; `NlpApp::make_contact_sheet` renders them from the thumbnail sources.

Conversion quality is measured on `testchart.rs`, a ColorChecker modelled on C-41 film. `pipeline::tests::chart_quality` and `dominated_scenes_stay_neutral` hold the metrics; their bounds only tighten. The chart is a 3-channel model and can mislead on colour questions, so check engine changes on real scans too: `scan_check.rs` converts every roll folder as the automatic convert does (no sidecars read or written) and reports analysis confidence, clipping, near-neutral cast per tone, chroma, exposure and their spread across each roll. Real scans have no reference colours, so compare against a baseline `stats.json` kept outside the repo rather than gating on values; stock-typical casts are film character. Bump `settings::ENGINE_VERSION` when analyses change meaning, and `sidecar::VERSION` when stored analyses or rolls change shape.

Crop shape is `Settings::crop_aspect` (`CropAspect`: Original by default, Free, or a fixed ratio that follows the frame's orientation). `frame::detect` trims its result to it with `fit_aspect`, and the editor's lock (`lock_aspect`) keeps drags at the ratio. It is geometry, not part of `AnalysisKey`.

Key data types live in `settings.rs`: `Settings` holds the per-image edit state, `ExportSettings`, `FilmMetadata` and `AnalysisKey`. `AnalysisKey` is the subset of settings the analysis depends on. If you change one of those fields, the frame needs re-analysis ("Convert"). Any other edit only rebuilds the `Renderer`. A new setting that affects analysis must go into `AnalysisKey`.

Persistence (`sidecar.rs`):
- `<image>.nlp.json` in the `NLP/` subfolder of each scan folder holds settings, analysis and roll data.
- `NLP/roll.json` holds the roll info (`RollInfo`: name, date, film metadata, notes). It is asked for the first time a folder is opened (`app/roll.rs`), and frames without their own film details inherit it.
- App defaults, last folder and the Projects list (`projects`): `dirs::config_dir()/nlp-studio/defaults.json`. `Defaults.scan` keeps the Scan panel's choices (resolution, IR, multi-exposure, passes, and per scanner the flatbed source and the gamma-encoded switch).
- Scans: `scan_NNN.dng` (or `.tif` for gamma-encoded flatbeds) in the roll folder, OpticFilm IR planes as `NLP/scan_NNN.ir.tif`. The OpticFilm calibration cache is the driver's: `dirs::cache_dir()/opticfilm/calib_v2.json`, in pyopticfilm's format.
- Decoded proxy cache: `dirs::cache_dir()/nlp-studio/proxies/`, keyed by path, size and mtime.

New `Settings` fields need `#[serde(default)]` compatibility so existing sidecars still load.

**`src/app/`**: the eframe GUI.
- `mod.rs` holds `NlpApp`: the `Frame` list, Folder/Editor `View`, undo/redo and toasts. It also contains the kittest UI tests.
- `roll.rs` holds roll info and the Rolls start screen (`defaults.projects`). A row's details and frame strip load in a background job as it comes into view (`JobResult::RollSummary`, `RollCover`), never touching disk on the UI thread: picks first, then evenly spaced unflagged frames, rendered from cached thumbnails and never decoded from a RAW. A missing folder offers Locate. New roll chooses or creates a folder and opens its empty grid, which is where Scan lives. "Add film details" opens the roll first, so the stock's crosstalk reaches the frames.
- `folder.rs` holds the welcome screen (first run only) and the roll's two bars. `widgets::drop_overlay` is the drag feedback on both start screens. The rule: the top bar is the roll, which frames are on show, and what goes in or out (breadcrumb with film stock, the grid filters All / Picks, plus Unflagged once culling has begun and Rejected once a frame is rejected, the ⋯ menu, Scan, and Export fixed in the far corner); the status strip at the bottom is the selection and the thumbnail size. Selection changes what a control acts on, never where it is: Export, Convert and the contact sheet take the selection, or else the frames on show, and with nothing selected Export and the contact sheet leave rejected frames out (`export_scope`, `export_label`). Scan source is in Roll info; the bar shows its chip only for a mixed roll or a single file. Copy / paste settings and Convert are in the ⋯ menu and on right-click; the Convert dialog has a "Balance as a roll" switch, on by default only for the whole roll. An open roll shows its grid even while empty, with a hint to drop files or Scan. `grid.rs` is the grid itself: uniform Lightroom-style tiles in the editor canvas's neutral grey on the window's dark, with the picture centred in its own shape and a header that holds everything about the frame, so nothing sits on the picture: frame number, pick / reject flags (P / X / U, stored as `Sidecar::flag`; each has a fixed slot, which turns into its button while hovered), the name while hovered, and on the right the status dots (a solid dot marks a frame left out of the roll's balance, a ring one not converted; a tooltip says which). Also box selection, the selection's part of the status strip (`selection_strip_ui`: pick / reject, rotate, deselect; frames the filter hides leave the selection), negatives (hold N, or the ⋯ menu) and a Space quick look rendered from the proxy. `shortcuts.rs` is the `?` keyboard shortcut sheet; keep it in step with new shortcuts. `editor.rs` is the single-frame editor: a top bar built like the grid's (roll / frame / film stock, then ⋯ and Export in the corner), the canvas, the bar under it (crop, compare, clipping, flags, zoom, previous / next frame, filmstrip toggle), crop/straighten (it swaps the bar under the canvas for a crop bar and leaves the sidebar and picture where they are: aspect, with Free as a real choice, portrait / landscape swap, rotate, flip, a ruler centred on 0 with a typed value and a draw-a-level-line tool, Detect frame, Reset, Cancel, Done; turns and flip are pending until Done; thirds show only while dragging) and the sidebar (a Histogram / Curves toggle, Basic, Colour, then Finishing (Glow / Fade, Burn / Dodge), closed unless opened or edited; a Film & roll dialog in the ⋯ menu; Sharpening is an export setting). `widgets.rs` holds the dark graphite theme (colour tokens in `theme`, Inter embedded from `assets/fonts/`), the shared controls and the vector icons. Use `theme::*` tokens and `widgets::primary`/`ghost` rather than ad-hoc colours, and `widgets::shortcut` for OS-correct shortcut labels.
- `auto.rs`: frames not converted when a folder opens are auto-cropped and converted in batches as their proxies load, then balanced as a roll (exposure variance → by images, with a banner, no modal). Converting/unconverting by hand releases a frame; `Defaults::manual_convert` turns it off. `pipeline::detect_source` picks the scan source (LinearRaw DNG or a VueScan/SilverFast Software tag → VueScan / SilverFast DNG); Roll info (or the folder bar's chip, when shown) changes it for the roll. Exports of unconverted frames wait here for their conversion.
- `history.rs`: app-wide undo/redo; a step holds the settings of every frame one action changed. Batch edits outside the editor call `record(&idx)` first; the editor records through `track_history`.
- `jobs.rs` runs all heavy work on the rayon pool and returns `JobResult`s over an mpsc channel, which the UI polls each frame. Frames load at `PROXY_SIZE` (1024 px) for thumbnails and analysis, and at `EDITOR_SIZE` (2048 px) for the editor preview. Exports decode at full resolution.
- `gpu.rs` + `preview.wgsl`: with wgpu, the editor preview is a paint callback running the renderer's dodge, curves (per-channel tables in rgb, the tone profile in alpha), look and output conversion in a shader (no sharpening). The density texture's alpha holds the dodge low-pass. While the straighten angle is dragged, `editor.rs` previews a cached 1024 px negative without the low-pass (`NegData::new(neg, false)`) and leaves the histogram dimmed until release. `gpu_preview_matches_the_cpu_renderer` checks it against `Renderer::render`; keep the shader in step with `curve.rs`/`look.rs`. The CPU renders a 1024 px copy for histogram, readout and clipping, and remains the fallback.
- `picker.rs`: native macOS NSOpenPanel via `objc2`, with `rfd` elsewhere.
- `scanner.rs` + `scan_panel.rs`: scanning into the open roll from Plustek OpticFilm scanners (the `opticfilm` driver crate in `scanners/opticfilm`, GPL-3, a parity-tested port of pyopticfilm; its README covers validation) and from SANE devices such as flatbeds with a transparency unit (the `sane` crate in `scanners/sane`: libsane loaded at runtime with `libloading`, from `$NLP_SANE_LIB` or the Homebrew / distribution paths, so the app runs without it; macOS and Linux only). A dedicated thread owns the open scanner (SANE is not thread-safe) and reports `ScanEvent`s through the job channel (`JobResult::Scan`); it also lists devices (`ScanCmd::Refresh`), hiding SANE's view of OpticFilms, which are driven natively. `ScannerInfo` describes either kind as capabilities. The Scan panel (folder top bar; an open roll shows its grid even while empty) prescans, renders the prescan as a positive with the default conversion, and scans the framed area — one box for film scanners, a box per frame on flatbeds, scanned in turn — as `scan_NNN.dng`, a LinearRaw DNG written by `engine::scan_dng` (rawler's DNG writer, sRGB `ColorMatrix1`), so scans open as a VueScan / SilverFast DNG source. For SANE, `sane::Device::prepare_film` picks the film source and sets colour, 16-bit, positive film type and gamma off; flatbeds whose data is still tone-curved are marked gamma-encoded per scanner (`Defaults.scan`) and save a TIFF that opens as a TIF Scan. The OpticFilm IR plane goes to `NLP/scan_NNN.ir.tif`, outside the frame list; nothing reads it yet. `add_scanned_frame` puts each new file in the grid, where it auto-converts and the roll pass runs again. Simulated scanners (debug and test builds, or `NLP_FAKE_SCANNERS=1`) are the OpticFilm mocks on the driver's virtual clock (GL128 models on its AFE simulator, so calibration completes) and the `sane` crate's simulated flatbed. Locked OpticFilm models (`scan_ready == false`) open for status only. Status: neither path has run on real hardware yet; the SANE path is tested against real libsane's `test` backend.

## External assets

None required at runtime. libsane is optional: when it's missing, only SANE scanners are unavailable (`NLP_SANE_LIB` overrides where it's looked for). The looks are native data in `assets/looks.json` (embedded with `include_str!`), measured from the plugin's enhanced looks; the plugin's tone profiles are fitted curves in `curve.rs`. The film crosstalk matrices in `crosstalk/*.toml` (from NegPy, GPL-3, for personal use; see `crosstalk/README.md`) are embedded the same way and picked by `Settings::crosstalk`. VueScan / SilverFast DNGs are set as the scan source by hand.
